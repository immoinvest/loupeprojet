# Feature Discovery + Specs : Référentiels (données publiques pré-agrégées)

## Demande

Fiche `referentiels` du tronc commun des sessions parallèles (13/09/2026) : les données publiques qui n'ont pas d'API exploitable en direct sont pré-agrégées chaque mois par une GitHub Action et publiées sur Cloudflare R2 en petits fichiers par département ou par commune, que le navigateur lira directement (via le Worker `/proxy` plus tard). Le chargement de ces fichiers par l'application appartient à la feature `enrichissement-marche`.

### Volumes et contraintes mesurés

- DVF 2025 : 2,3 Mo gzip pour les Bouches-du-Rhône, 230 Ko pour la Corse-du-Sud (8 300 lignes, 3 700 mutations). Une mutation compte de 1 à 60 lignes ; les lignes d'une même mutation sont contiguës dans le fichier (vérifié : 0 rupture sur 3 739 mutations). Un tiers des lignes n'a pas de type de local (parcelles nues), 1 % n'a pas de coordonnées.
- Pour couvrir 24 mois glissants, il faut lire jusqu'à trois dossiers annuels (le dossier de l'année en cours n'apparaît qu'en octobre, avec le premier semestre).
- France entière : environ 300 téléchargements (400 Mo) et 10 millions de lignes, traitées en flux ; environ 34 000 fichiers de commune par millésime DVF.
- Conséquence : `wrangler r2 object put` (un processus par objet, 1 à 2 s) n'est pas viable pour 34 000 fichiers (10 heures ou plus). La publication se fait par `aws s3 sync` vers l'API S3 de R2 (outil préinstallé sur les runners GitHub), avec un jeton R2 « Object Read & Write ». Écart assumé par rapport à la fiche, signalé à Pierre.

## Périmètre

- **IN** : ce qui précède ; tests à 100 % sur la logique avec de petits extraits réels dans `data/tests/fixtures/` ; aucune requête réseau dans les tests (téléchargement injecté).
- **OUT** : `apps/*`, `packages/moteur`, `.github/workflows/ci.yml` ; lecture de ces fichiers par l'application (`enrichissement-marche`) ; création du bucket et des secrets (compte Cloudflare de Pierre, marche à suivre dans le rapport final).

## Auto-validation critique

- **DVF, règles de filtrage** : nature « Vente » uniquement (les VEFA, échanges, adjudications et expropriations sont écartés : le comparable Loupe est le marché de l'ancien) ; exactement un local d'habitation par mutation et aucun local commercial (les ventes multi-lots ne permettent pas d'attribuer un prix au logement) ; une seule valeur foncière par mutation (plusieurs dispositions = prix ambigu) ; surface 9 à 1 000 m², prix au m² 300 à 40 000 € (élimine les ventes symboliques et les fautes de saisie). Ces bornes sont des constantes nommées, documentées dans `SOURCES.md`. Les ventes sans coordonnées restent dans le CSV (colonnes vides) : elles comptent pour la commune, pas pour un rayon.
- **DVF, fenêtre** : 24 mois se terminant à la dernière vente connue du département ; le dossier de sortie porte l'année de cette dernière vente. Les départements se terminent à quelques jours d'écart, sans effet pour le navigateur.
- **ANIL** : loyers charges comprises et biens loués vides ; l'application applique −8 % puis les majorations meublé/colocation (spec). `maille: true` signale un indicateur emprunté à une maille plus large : confiance faible, à afficher.
- **Taxe foncière** : `total` = commune + syndicats + intercommunalité + GEMAPI + TSE ; la TEOM est récupérable sur le locataire, donc publiée à part et exclue du total. Paris, Lyon et Marseille sont au niveau de la commune (75056, 69123, 13055) : l'application passe par `communeParente` du fichier communes.
- **Usure** : aucune source ouverte automatisable sans clé d'API ; la saisie trimestrielle est le seul chemin honnête. L'oubli est couvert par `perime: true` et un avertissement dans le journal de l'Action ; l'API Webstat (clé gratuite) est notée comme évolution possible.
- **Publication** : `aws s3 sync` par préfixe, avec `--delete` limité au préfixe généré et seulement si le dossier local n'est pas vide ; une source en échec n'efface rien. Écart à la fiche (`wrangler r2 object put`) justifié par le volume.
- **Millésime ANIL** : l'URL du jeu change chaque année (nouveau slug) ; la constante est à mettre à jour une fois par an, ce que `SOURCES.md` rappelle. Les URL passent par `data.gouv.fr/fr/datasets/r/<id>` (stables, redirigées vers la dernière version).
