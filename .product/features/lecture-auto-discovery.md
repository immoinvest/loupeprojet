# Feature Discovery + Specs : Lecture automatique d'un lien collé (`lecture-auto`)

## Demande

« Je veux vraiment que copier-coller un lien fonctionne directement, même si ça impose d'ouvrir un nouvel onglet qui automatiquement déclenche la lecture via extension […] le plus smooth possible, et assure-toi que toutes les informations possibles soient capturées des différents annonceurs, afin qu'il y ait le moins de choses possible à remplir à la main. » (Pierre, 13/09/2026, après avoir écarté la lecture côté serveur : « Gardons le plan initial ».)

## Analyse

- **Quoi** : l'utilisateur colle le lien dans Nouveau projet. Si l'extension Deklic est installée, la page Deklic le lui demande ; l'extension ouvre l'annonce dans un onglet de son navigateur, la lit, referme l'onglet et renvoie la capture ; le formulaire Vérifier se remplit. C'est le parcours prévu par la spec (« l'utilisateur colle l'URL dans Loupe et l'extension ouvre la page en arrière-plan, la lit, la referme ») et il reste conforme à l'ADR-002 : lecture dans le navigateur de l'utilisateur, à sa demande, jamais par nos serveurs. Sans extension, le parcours actuel (texte collé, favori, saisie) reste là, avec une invitation à installer l'extension.
- **Pourquoi** : aujourd'hui coller un lien ne suffit pas (il faut encore copier le texte ou cliquer l'extension sur l'annonce). Et le relevé du 13/09/2026 sur de vraies annonces montre que les règles de la feature `extension` ratent l'essentiel sur trois portails sur cinq.

## Périmètre

- **IN** : ce qui précède ; `apps/web/src/annonces/` et `NouveauProjet.tsx`, `FormulaireProjet`/`valeurs` pour les nouveaux champs.
- **OUT** : lecture côté serveur (écartée par Pierre), appel du LLM `/extract` pour combler les trous (chaîne principale, `enrichissement-marche`), photos, historique de prix, publication sur les stores.

## Auto-validation critique

- **Légal** : la lecture reste dans le navigateur de l'utilisateur et à sa demande (il colle un lien) ; l'onglet ouvert est un onglet normal de son navigateur, avec ses cookies ; la requête `/realEstateAd.json` de Bien'ici est celle que la page ferait elle-même. Aucun serveur Deklic ne voit l'annonce.
- **Permissions** : l'extension demande désormais l'accès aux cinq portails et aux pages Deklic (nécessaire pour ouvrir et lire un onglet sans clic sur l'annonce). C'est plus que `activeTab` : le README et le popup l'expliquent. Aucune requête vers nos serveurs, aucun stockage.
- **Fragilité** : les plateformes changent ; les règles restent un JSON par portail, corrigeable sans code ; si tout échoue, le texte collé reste proposé immédiatement.
- **Anti-robot** : LeBonCoin et SeLoger peuvent présenter un contrôle ; l'onglet affiché en second essai laisse l'utilisateur le passer, sans quoi l'échec est signalé proprement.
- **Ce qui reste à remplir** : charges et taxe foncière chez SeLoger/Logic-Immo/PAP ne sont que dans le texte (lu par les règles de texte du web) ; le LLM `/extract` les comblera quand la chaîne principale le branchera.
